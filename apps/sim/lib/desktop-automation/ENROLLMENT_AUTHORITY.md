# Local enrollment authority

`createNativeEnrollmentAuthority(config)` implements the existing internal `EnrollmentAuthority` port. `null` returns no authority; invalid configuration refuses. There is no implicit environment configuration, remote CA, browser principal, trust-store installation or desktop cookie. Only a server administrator may provide the configuration. The session/workspace service remains responsible for authorization and proof-of-possession before calling `issue`.

The configured installation ID and canonical HTTPS origin, pinned absolute OpenSSL **3** executable, public CA certificate/hash, encrypted PKCS8 key, passphrase Buffer, private spool and whole-day certificate policy (1–30) are required. The CA lifetime must cover that policy. OpenSSL must be installed separately by the operator; there is no installation fallback. Configuration never contains an unencrypted key. The factory owns a passphrase copy; `close()` erases that copy and refuses future operations (the caller must await pending operations first). JavaScript/OpenSSL memory zeroization is best effort.

CSR verification uses native `req -verify` and Node public-key import; allowed keys are RSA 3072–8192 and EC P-256/P-384. Proof-of-possession uses SHA-256 and a canonical base64url signature over the **exact** service challenge string. The issuing operation uses `x509 -new -force_pubkey`, not CSR extension copying: agent UUID subject, installation/origin/binding URI SANs, critical CA:false/digitalSignature and clientAuth only. Node reads the returned certificate and checks CA signature/issuer, SPKI, serial, subject/SAN, EKU, lifetime and fingerprint before a result can be published.

## Durable effects and refusal

An exclusive UUID directory plus fsynced immutable intent claims an issuance ID before the native signing command. The full service binding digest and the authority configuration fingerprint must match. A repeated call consults the existing receipt only; an incomplete intent, malformed receipt, unknown acknowledgement, collision or native failure is **unknown**, never a request to sign again. The certificate and its checksum receipt are exclusive files; no overwrite or automatic repair exists. Public PEM may be returned; the CA key is never returned or copied into the spool.

Local revocation is an exclusive fsynced marker and is rechecked before signing, publication and lookup. It can precede issuance. This registry prevents further successful adapter results; it is **not** an OCSP service, CRL distribution or enforcement at a TLS ingress. The enrollment service separately arbitrates database revocation versus certificate activation. Runtime mTLS, trusted proxy identity, CA rotation and renewal remain separate work.

Spool directories are owner-only and filesystem ancestors must be real, owner/root controlled and not writable by other users. Files use exclusive/no-follow opens, owner permissions and a single hard link; reads check descriptor/path identity and bounded length. This does not isolate mutually hostile processes under the same OS account or an administrator capable of replacing the CA/runtime. Do not share the spool between different configured authorities. The executable is a separate administrator-maintained installation: canonical owner/root-controlled ancestors may be group-writable only for group IDs explicitly recognized in administrator configuration (`openssl.administratorGroupIds`, default empty; for example macOS admin GID80 for Homebrew Cellar); world-write is refused, the executable itself rejects group/world write and is SHA/inode-pinned and revalidated immediately before every spawn. Administrators maintaining that tool and its dynamic libraries are trusted; this is not a sandbox against concurrent administrator replacement.

## Native subprocess boundary

No shell, passphrase argv, caller environment or globally modified environment is used. Only explicit inherited CA/key/public-key/extension descriptors are given to OpenSSL. The passphrase travels through finite FD3 followed by LF and EOF. The signer has empty stdin (`/dev/null`); CSR parsing uses separate stdin. An owned new process session avoids inheriting a controlling terminal. This matters on macOS: OpenSSL's UI opener can otherwise fail `TTY_get` on Node's stdin socket with errno102 **before** consuming the supplied passphrase. No unencrypted-key fallback is permitted.

Commands allow at most 16KiB input, 32KiB stdout, 8KiB stderr, four concurrent native children and ten seconds plus 250ms termination grace. Prefixes and truncation/exit state are retained privately before interpretation; stdout/stderr files are 0600. Resolution waits for child and stream closure; signing is never retried after timeout. Private command/configuration causes are bounded and never attached to the public fixed refusal. Records require operator retention limits; this module does not silently delete uncertain issuance evidence.

Tests generate a fictive CA and hostile-extension CSR locally, then exercise the real pinned OpenSSL and Node crypto. They do not qualify Linux deployment, mTLS, Windows, routes, databases or a production CA.
